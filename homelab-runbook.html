Isolation & data

Each Hermes container gets its own mode‑restricted bind mount at a <per-agent state path>, not readable by the host's own primary account, plus a read‑only view of a <shared data path> (currently empty). hermes‑4 does not get that read‑only shared‑data mount — a copy‑paste leftover was found and removed. hermes‑3 is the exception: it gets read‑write access to the shared data and its own Docker network, which is also the only network whisper‑ivrit joins — that's the deliberate seam that lets the household agent use shared STT without exposing it to the personal agents.

Each agent also has a persistent GBrain (knowledge/memory) and an Obsidian‑compatible Markdown vault, isolated the same way: hermes‑1/hermes‑2/hermes‑4 each run their own local GBrain process against their own database — nobody else can reach it, by construction (no shared filesystem path, no shared network, no credential). The household brain is different: it's the one case with more than one legitimate reader at different permission levels, so it runs as a small always‑on service on its own internal network, and hermes‑1/hermes‑2 hold a read‑only token for it while hermes‑3 holds read‑write — verified with a scoped write attempt against the read‑only token, which the server rejects (insufficient_scope). hermes‑4 is not on that network at all; it can't even resolve the household brain's hostname.

<manual backup path> holds two manual snapshots (5.3 GB, taken 2026‑08‑31) from before the sops secret‑encryption changes. No timer or cron job produces new ones — this was a one‑off precaution, now superseded by the nightly whole‑VM PBS backup.

Backups & disaster recovery

Full runbook: homelab‑stacks › docs/RESTORE.md

Restore, fastest to slowest

01
PVE web UI · select the VM → Backup tab → pick a snapshot → Restore (in place or to a new VMID).
02
PBS web UI (PBS host, port 8007) · browse snapshot contents or restore individual files without touching the whole VM.
03
CLI on the Proxmox host · pvesm list homelab-pbs --vmid 101 then qmrestore <volid> 101.
04
Full NUC loss · only recoverable if the USB datastore drive survived — see the caveat below and the full runbook for rebuild steps.
The datastore is one USB drive in the same box it protects. That covers accidental deletion, bad deploys, and Proxmox‑level mistakes — it does not cover the NUC itself dying, being stolen, or burning down. Real disaster recovery means periodically rotating the drive off‑site; without that habit, this is backup, not DR.
